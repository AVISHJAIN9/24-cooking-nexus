# 14.14 Observability, Logging & Site Reliability Operations

## 1. Plain English Overview
Observability provides deep, real-time visibility into an application's internal state through the "Three Pillars of Observability"—Logs, Metrics, and Distributed Traces—allowing engineers to detect anomalies, debug outages, and ensure high system reliability.

## 4. Observability Tools Comparison

| Tool / Category | Primary Pillar | Overhead | Scalability | Cost Profile | Fit for Cooking Nexus |
|---|---|---|---|---|---|
| **Pino (Recommended)** | Structured Logs | Ultra-Low (Fastest JSON)| High | Open Source | Standard for Node backend |
| **Winston** | Logs | Moderate (Transport tax)| Moderate | Open Source | Popular, but slower than Pino |
| **Prometheus + Grafana**| Metrics (Time-series) | Low (Pull model) | High (Mimir / Cortex)| Open Source / Low cost | Industry standard |
| **OpenTelemetry (OTel)**| Distributed Tracing | Low | Vendor-neutral | Open Source | Essential for microservices |
| **Datadog / Sentry** | Full-Stack APM & Errors | Ultra-Low (Agent based) | SaaS Scale | High ($$$ per host) | Great for automated crash alerts |

## 5. Golden Signals & SLI / SLO Definitions
- **Service Level Indicator (SLI)**:
  1. *Availability*: Percentage of successful HTTP 200/202 responses on `/api/vision`.
  2. *Latency*: 99th percentile (p99) response time for hazard ingestion.
- **Service Level Objective (SLO)**:
  1. 99.9% of `/api/vision` requests complete successfully over any rolling 30-day window.
  2. 95% of requests complete in $< 100\text{ms}$.
- **Service Level Agreement (SLA)**: 99.5% uptime commitment to smart kitchen appliance manufacturers.

---

## 6. What Breaks First at Scale?
- **At 10x**: Server disk space fills up with un-rotated `console.log` stdout text files.
- **At 100x**: Alert fatigue: poorly tuned alerts wake on-call engineers for benign 1-second transient network blips.
- **At 1,000x**: High-cardinality metric explosion in Prometheus if tracking metrics with dynamic user IDs as labels.

---

## 7. Senior Engineer Improvements
1. **Correlation IDs**: Inject an `x-correlation-id` header in Express middleware. Pass this ID into every database query, log message, and upstream AI request so an engineer can trace an entire request across all services with a single search.
2. **Crash Reporting**: Integrate **Sentry** in both the React frontend and Express backend to capture unhandled exceptions with full stack traces and client breadcrumbs.
